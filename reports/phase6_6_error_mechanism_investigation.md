## 1. Executive Summary & Epistemological Status

This report documents an exploratory, post-hoc investigation into the mechanisms driving elevated false-alarm rates in the frozen Phase 6.3 $L=5$ failure prediction models evaluated during Phase 6.4.

> [!CAUTION]
> **Strict Epistemological Disclaimers:**
> 1. **Post-Hoc Status:** This investigation is strictly exploratory and post-hoc. The Phase 6.4 confirmatory holdout dataset has already been unblinded and scored.
> 2. **No Winner Selection:** The official confirmatory verdict **`NO_OPERATIONAL_WINNER`** remains permanent and unaltered. All four candidate models failed both operational gates ($\text{FAR} \le 12.0\%$, $\text{FPR} \le 5.0\%$).
> 3. **Holdout Immutability:** No models were retrained, no hyperparameters were altered, no decision thresholds were adjusted, and no predicted labels or probabilities were modified.
> 4. **Association vs. Causation:** All empirical patterns identified between telemetry features, parent jobs, and false alarms are reported strictly as **observational statistical associations**, not proven causal mechanisms.
> 5. **Scope Limitation:** Generalization findings are limited to application-level workloads within the **Google May 2011 cluster trace (cell A)**; they do not establish generalization to external datacenter datasets.

```
========================================================================================
INVESTIGATION SUMMARY: ROOT CAUSES OF HIGH FALSE-ALARM RATES
========================================================================================
1. Critical Alert Skew      : 73.1% - 97.1% of false alarms are Critical (not Warning).
2. Telemetry Missingness    : Missing hardware CPI telemetry (cpi_missing_fraction_6)
                              is the #1 correlate of false alarms in pure normals (d = +1.2 to +3.0).
3. Extreme Workload Burst   : False alarms are heavily clustered in a small fraction of
                              parent jobs (Gini = 0.75 - 0.88; top 3 jobs drive 44% of RF FPs).
4. Premature Signal Capture : In failing entities, sequence models detect degradation 30-48 min
                              in advance, triggering alerts in normal windows (75.7% - 98.6% FPR).
5. Uncalibrated Argmax Rule : Training with ~10x loss weights on Critical combined with argmax
                              triggers Critical alerts at predicted probabilities as low as 0.336.
========================================================================================
```

## 2. Task 1: Audit of False-Positive Definitions & Arithmetic Invariants

To eliminate any ambiguity in false-alarm definitions, we recomputed all false-positive counts and verified every cohort denominator from first principles.

### 2.1 Formal Operational Definitions
- **False Positive (Window Level):** A primary window whose true label is $y=0$ (Normal) but whose model prediction is $\hat{y} \in \{1, 2\}$ (Warning or Critical).
- **Pure-Normal Entity FAR:** The proportion of evaluable pure-normal entities ($N=198$) that trigger at least one alert ($\hat{y} \in \{1, 2\}$) across their evaluable lifetime.
- **Pooled Normal-Window FPR:** Total false positive windows divided by all primary normal windows ($N=4,811$).
- **Disaggregated Normal Windows:**
  - **Pure-Normal Cohort ($N=4,515$ windows):** Windows generated by tasks from the 198 evaluable pure-normal entities that never experienced a failure.
  - **Failing-Cohort Normal Windows ($N=296$ windows):** Normal windows ($y=0, \tau > 30$ min) generated during the lifetimes of the 137 failure entities.

### 3.3 Diagnostic Insights: Divergent Error Mechanisms
1. **Pure-Normal Entities:** False alarms are overwhelmingly associated with `cpi_missing_fraction_6` ($d = +1.21$ to $+2.95$, with bootstrap lower bounds strictly $> 0.8$). In pure-normal tasks, benign collection gaps or task idling mimic the telemetry starvation that models learned to associate with crash episodes during training.
2. **Failing-Cohort Normal Windows:** False alarms are driven by **pre-failure volatility and trends** (`cpu_rolling_range_6`, `cpu_rolling_std_6`, `cpu_trend_slope_6`, $d > +1.0$ in RF). Missing CPI is *not* the primary driver in failing normal windows ($d = -0.57$ in RF, $+0.39$ in LSTM). The sequence models are responding to real physical volatility.

## 5. Task 4: Label-Boundary Behavior & Temporal Horizons

We analyzed the temporal distribution of false-positive alerts relative to each task's lifetime and failure episode timestamps.

### 5.1 Temporal Subgroups Partition
The 5,511 primary evaluation windows partition into four mutually exclusive timing regimes:
1. **Critical Horizon ($0 < \tau \le 15$ min, $N=400$):** Pre-failure catastrophic period ($y=2$).
2. **Warning Horizon ($15 < \tau \le 30$ min, $N=300$):** Early warning degradation period ($y=1$).
3. **Failing-Cohort Pre-Failure Normal ($30 < \tau \le 48.3$ min, $N=140$):** Normal windows preceding a confirmed failure episode ($y=0$).
4. **Failing-Cohort Post-Failure Recovery ($N=156$):** Normal windows occurring after a task restart/recovery where no subsequent failure occurred ($y=0$).
5. **Pure-Normal Entities ($N=4,515$):** Normal windows from tasks with zero failures throughout their observation window ($y=0$).

```

| Model Candidate                   | Pre-Failure Normal Windows  | Post-Failure Normal Windows | Pure-Normal Task Windows    | Elevation Ratio    |
|                                   | (tau in [30, 48] min, N=140)| (Crash recovery, N=156)     | (Benign lifetime, N=4,515)  | (Pre-Fail / Pure)  |
+-----------------------------------+-----------------------------+-----------------------------+-----------------------------+--------------------+
| Random Forest                     |     12 / 140 ( 8.57%)       |     39 / 156 (25.00%)       |    978 / 4,515 (21.66%)     |       0.40x        |
| Temporal LSTM                     |    138 / 140 (98.57%)       |    100 / 156 (64.10%)       |  1,055 / 4,515 (23.37%)     |       4.22x        |
| Compact Temporal Transformer      |    113 / 140 (80.71%)       |     75 / 156 (48.08%)       |    787 / 4,515 (17.43%)     |       4.63x        |
| Representation Hybrid             |    106 / 140 (75.71%)       |     86 / 156 (55.13%)       |  1,475 / 4,515 (32.67%)     |       2.32x        |
+-----------------------------------+-----------------------------+-----------------------------+-----------------------------+--------------------+
```

### 5.2 Key Discovery: Premature Degradation Capture
- In the sequence models (LSTM and Compact Transformer), **$80.7\%$ to $98.6\%$ of normal windows occurring 30 to 48 minutes prior to failure triggered false alarms**.
- This is a **$4.2\times$ to $4.6\times$ elevation** relative to pure-normal tasks.
- *Mechanism:* Physical degradation in distributed cluster containers (memory leaks, thread deadlocks, GC pauses) begins well before the arbitrary 30-minute pre-registered Warning boundary. The sequence models successfully learn and detect this pre-failure pattern, but because the pre-registered protocol strictly enforces $y=0$ for $\tau > 30$ min, these detections are penalized as false positives.

### 6.2 The Uncalibrated Argmax Problem
1. **Low Effective Triggering Threshold:** Under uniform argmax in a 3-class system, an alert triggers whenever $P(\text{Normal}) < \max(P(\text{Warning}), P(\text{Critical}))$. Across all four models, the minimum probability required to trigger a Critical alert is **$0.336$ to $0.359$**. A model need not be confident that a failure is imminent; it only needs to be slightly uncertain that the container is normal.
2. **Softmax Saturation in Transformers:** In Compact Transformer, the median predicted Critical probability on false positive windows is **$0.993$**. Uncalibrated cross-entropy training with high weights forced the network into extreme saturation on telemetry anomalies, causing near-binary $0$ vs $1$ output distributions.

### 7.1 Directives for Future Confirmatory Studies
Any future failure prediction architecture intended for production deployment must implement three fundamental protocol improvements:
1. **Pre-Registered Pareto Threshold Tuning on Development Splits:** Models must not use raw argmax. Decision thresholds must be tuned on validation data using cost-sensitive utility functions (e.g., penalty ratio of 20:1 for false alarms vs missed failures) and frozen before scoring holdouts.
2. **Disentangled Hardware Missingness Modeling:** Missingness indicators (`cpi_missing_fraction_6`) must be isolated or explicitly handled using masked sequence modeling so that container idling does not trigger catastrophic crash warnings.
3. **Multi-Horizon Degradation Labeling:** Pre-failure label horizons should incorporate a gradual degradation tier ($\tau \in [30, 60]$ min) rather than treating 30.01 minutes as identical to healthy steady state.
4. **Independent External Cohort Evaluation:** Re-evaluated models must be scored on a newly sampled confirmatory cohort drawn from different temporal partitions or cluster cells.
